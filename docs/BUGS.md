# Nickel bug bash

Local file-backed verification only. The pass started at `8ffa448` and was reconciled with wallet, Nace and result-animation integration at `0bb9b93`. All money was simulated. No Convex deployment, Keiki request, text message, Stripe session, image generation or paid model request was made.

Severity: P1 changes another player's identity, points or money; P2 breaks a journey or gives an incorrect answer; P3 is a minor presentation problem. Product decisions and work owned by the parallel passes are separated below.

## Fixed

| ID | Severity | Reproduction | Actual before fix | Expected and fix |
| --- | --- | --- | --- | --- |
| F01 | P1 | Claim a card, fund its fake wallet, then POST `/api/turn` without its cookie, supplying its name/phone and `Nickel, cash out all`. Repeat from a different signed-in card. | The text endpoint bypassed the write gate and let the supplied sender withdraw someone else's balance or cancel their pot. | Browser turns use the session's name and phone. Anonymous named mutations return 401; anonymous discovery still works. A session cannot rename itself through text to change the actor. Trusted messaging retains sender identity. `server/auth.ts`, `server/brain.ts`. |
| F02 | P1 | Start without `NICKEL_TURN_SECRET`, then request another phone's player-card link through `/api/turn`. | Every caller was trusted and could mint a claim link. | Missing configuration fails closed. Only the shared-secret transport mints messaging claim links; ordinary browser sessions still work. `server/auth.ts`. |
| F03 | P1 | POST a `photoUrl` to `/api/turn` with another player's phone. | An untrusted request could launch the importer and replace their photo. | Untrusted imports return 403 and direct the player to their authenticated card. The route also checks transport trust before spawning the importer. `server/auth.ts`, `server/index.ts`. |
| F04 | P1 | Create an RPS challenge, then POST a winning result with an unrelated `opponent`, or as a third player. Use a guest to target a claimed rival. | Arbitrary rivals lost Nickels, and outsiders could submit results against the round's opponent. | The rival comes from the round, named challenges accept only their participants, and guest results cannot debit a claimed rival. `server/brain.ts`. |
| F05 | P1 | Finish an RPS challenge as one participant, then submit the same round as the other participant or from a second tab. | The second name passed the per-name duplicate check and moved the stake a second time. | One RPS result applies to both participants. | F06 | P1 | Play, fund a wallet, pay a buy-in, draft and remember a fact; edit the player-card name. | The new name started over, old names remained on the leaderboard, and name-keyed money and memberships stayed behind. | A card rename moves its points, stats, results/idempotency identity, round participants, rosters, pot membership, wallet balance/ledger, payout ownership, pick history and authored memory. `server/brain.ts`, `server/hub.ts`. |
| F07 | P2 | Maya challenges Sritej; Sritej opens the RPS link. | Sritej faced Sritej, and a result could count the same person as winner and loser. | Both the page and scorer resolve the challenged player's rival to the challenger. `apps/preview/play.html`, `server/brain.ts`. |
| F08 | P2 | With Nace unavailable, repeatedly request Krillion; answer an ocean-animal prompt with `whale`. | Three prompt families used a country-only local grader, so valid answers wiped out. | New offline rounds select the prompt supported by the local grader. | F09 | P2 | Submit Wordle `0/6`, `7/6`, nonsense tries, negative seconds, rarity 99, or a result for closed `krill-87`. | Impossible and closed results earned Nickels. | These inputs return `ok:false` without a write. Existing completed rounds remain idempotent. `server/brain.ts`. |
| F10 | P2 | POST a number/object as a profile name, result name, or fantasy pick. | String operations threw instead of rejecting the input. | Non-string names/picks fail normal validation. `server/brain.ts`. |
| F11 | P2 | Draft Tony and text `Nickel, Tony +500`. | Chat announced `+500` even though `scorePick` rejected it and the stored score was unchanged. | The reply explains the 100-point limit and reports the unchanged score. `server/brain.ts`. |
| F12 | P2 | Create any fantasy league, then text `Nickel, fantasy league for nba`. | Nickel reopened the previous topic instead of creating the requested league. | An explicit new topic creates that league. `server/brain.ts`. |
| F13 | P2 | Text `Nickel, it's rigged`, `I'm done`, or say `I'm cooked` after onboarding. | Casual statements could rename the sender to Rigged, Done or Cooked. | Known names are not replaced by casual introductions, common non-name statements are excluded, and untrusted browser text cannot alter the actor. Explicit trusted introductions remain supported. `server/brain.ts`. |
| F14 | P2 | Text `Nickel, draw me as the loser` or `Nickel, loser has to wear a wig`; ask `show me who won`. | The first two earned an insult reaction; the last could ask for a photo. | Art and punishment commands take precedence over insult matching; result questions are not art commands. `server/brain.ts`. |
| F15 | P2 | With no open pot, text `Nickel, I'm in`, `who paid`, or `who's in`. | Nickel answered with a gibberish comeback and sometimes a question reaction. | It explains that no buy-in exists and shows the proposal command. `server/brain.ts`. |
| F16 | P2 | Text `Nickel, remember` or `Nickel, I can't remember who won`. | The empty command got a comeback; the latter stored `Who won` as a fact. | The empty command asks what to remember; negative remembering statements do not write memory. `server/hub.ts`. |
| F17 | P2 | Remember `<b>Alex</b> owes <i>everyone</i> boba`, then query Alex. | Markup became `BAlex/b` and damaged both the fact and its person classification. | Tags are removed before person detection. | F18 | P2 | Send an insult/excuse in Messages, then another message before the delayed reaction arrives. | The reaction attached to whichever outgoing bubble was last, not the one that earned it. | Each send captures its own bubble before awaiting the reply. | F19 | P2 | Open Krillion directly rather than inside the Messages preview, finish and tap Done. | Done only posted an iframe callback and did nothing in the standalone page. | Standalone Done opens `/h`; practice and embedded close callbacks keep their existing behavior. `apps/preview/play.html`. |
| F20 | P2 | POST an empty/invalid member to a pot agreement endpoint, or agree to a settled pot. | The route ignored `joinPot`'s error and replied `ok:true` although nothing changed. | A one-line route fix returns the actual error with 409/404. `server/index.ts`. |

Regression coverage for these fixes is in `server/fixes.test.ts`. The existing suites were retained; the markup test's incorrect expected output was corrected, not removed or loosened.

## Product decisions, not implemented in this fix pass

| ID | Severity / impact | Evidence and choice needed |

| D01 | P1 if real competition is expected | RPS challenges use `devMoves` generated by the server, not moves submitted by the other person. Wordle/Krillion challenges each run solo and do not settle a five-Nickel head-to-head stake despite the challenge text. Two people can open and submit, but that is not a true live/asynchronous match. Implementing real multiplayer/acceptance is a feature, not a local bug fix. |
| D02 | P1 if anti-cheat is expected | Wordle answers and RPS moves are embedded in the page; game outcomes remain client-reported. A signed-in participant can invent plausible results. F04/F05 stop arbitrary rival substitution and duplicate debits, but do not establish server-authoritative play. Decide the trust model before real money depends on these results. |

Reproduced: Sritej leads; Maya and Zed pay; Sritej takes their pot. Existing hub tests explicitly expect a non-payer to win another pot. The wallet/settlement policy needs a decision about eligibility and the competition window. It was not silently changed. |
| D04 | P2 | Insult/excuse matching remains keyword-based: `Nickel, who is the worst` or `Maya cheated` can receive a clapback/excuse. F14 protects concrete art/punishment/result commands; third-person banter and whether an excuse must follow a real loss require a reaction-policy decision or the parallel Nace classifier. |
| D05 | P3 | Names accept only ASCII letters and 14 characters. Markup and emoji are never executed, but `<img ...>` can normalize into a nonsensical ASCII name; non-Latin names are rejected. Choose supported name characters rather than inventing a new identity policy in this pass. |

## Verification and limits

- Baseline gate passed before edits. After wallet integration, the full gate runs with Stripe/OpenAI/Nace keys unset: `bun run typecheck && bun run test && bun run build`.
- A two-cookie-jar HTTP journey made 64 checked requests covering one-time claims/reuse, names, solo and challenge submissions for all three games, idempotency, fantasy creation/draft/write-in/chat scoring, demo wallet top-ups/buy-ins, paid status, settlement/balances, memory, invite, reactions, malformed input and chat impersonation. Leaderboard Nickels were compared directly to the temp file store.
- Chromium was driven at 390 by 844, with light/dark game/page checks, a real local photo upload, authenticated links without a name picker, a fresh Wordle, Krillion and an RPS challenge opened as the challenged person. Settled point breakdowns matched the stored totals. Both player identities were exercised through independent cookies; the second person's full game animations were not replayed in a second graphical browser context.
- Every Messages chip was clicked after claiming a card, including wallet buy-in agreement, and the composer was exercised. The console was read throughout the journeys; no unexpected browser errors or server exceptions were observed. Expected hostile-input HTTP errors are intentional.
- Missing/closed pages, reused claim links, a second device's rejected claim, empty names, long request rejection, safe display of HTML names/picks, a repeated result, a second player's RPS submission, reload/back and two-tab cases were checked across browser/API tests. Back/replay limitations are U01/U02, not claimed fixed.
- Real Safari/iOS, live iMessage delivery, Keiki/Vault delivery, real Stripe checkout/payout, image generation, Nace service availability, a live Convex deployment and production deployment were not tested. AI-dependent paths were disabled locally, not billed. No external credentials were changed.
